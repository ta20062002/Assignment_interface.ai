# Evidence

All checked-in evidence is generated by `node src/cli.js evidence` and contains only synthetic data. The journals and HTML snapshots are redacted before being written; they intentionally contain neither a literal member identifier nor a displayed balance.

| File | What it demonstrates |
| --- | --- |
| `capabilities/read-savings-balance.v1.json` | Approved, typed, parameterized capability produced by discovery. |
| `discovery-fixture.jsonl` | Full observe -> decide -> act -> record trace against the live local UI. The planner is explicitly labeled `recorded-decision-fixture` so it cannot be mistaken for a model API call. |
| `replay-success.jsonl` | Deterministic replay, no planner present, with a successful declared output. |
| `replay-not-found.jsonl` | A legitimate `member_not_found` business outcome. |
| `replay-session-expired.jsonl` and `handoff-session-expired.json` | A hard failure, intervention request, human ownership transfer on the same surface session, manual action, and resumption. |
| `snapshots/` | Redacted HTML evidence captured from the target surface. |

The application also has a genuine LLM discovery mode. It is intentionally not fabricated in a submission without the evaluator's API key:

```bash
export OPENAI_API_KEY='your key'
npm run demo:live
```

That writes a distinct redacted model-driven trace and draft artifact under `evidence/live/`. It uses the exact same recorder and local target as the fixture, but `OpenAIResponsesPolicy` makes one structured model decision per observed state.
